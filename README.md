# 台股觀察清單每日檢查工具

用 yfinance 抓日線，計算均線、RSI 等指標，用白話文給出訊號。
**只做資料分析，不會下單。訊號僅供參考，不是投資建議。**

## 安裝（只需做一次）

需要 Python 3.9 以上。在終端機進入本資料夾後：

```bash
python3 -m venv .venv                 # 建立獨立環境（Windows 同樣指令）
source .venv/bin/activate             # Windows 改用：.venv\Scripts\activate
pip install -r requirements.txt
```

## 執行（每天收盤後）

```bash
source .venv/bin/activate             # 每次開新終端機都要先做
python stock_checker.py
```

執行後會得到：
1. 終端機的摘要表（代號、名稱、收盤、離季線%、RSI、訊號）
2. `output/代號.png`：每檔一張 K 線圖（含 5/20/60MA 與成交量，紅漲綠跌）
3. `report.csv`：完整數字（含量比、距 52 週高點、持股損益），可用 Excel 開啟

## 修改設定（config.yaml）

- `watchlist`：要觀察的代號。上市/上櫃不用分，程式先試 `.TW` 再試 `.TWO`
- `names`：中文名稱（選填）
- `holdings`：你的持股（選填），格式見檔案內範例；有填才會檢查停損
- `stop_loss_pct`：停損比例，預設 `0.08`（8%）

門檻（過熱的 7%、RSI 75 等）在 `stock_checker.py` 最上方，可自行調整。

## 訊號意思

| 訊號 | 條件 |
|---|---|
| 多方 | 收盤在季線（60MA）之上，且季線比 5 天前高 |
| 站上季線但季線未向上，觀望 | 在季線之上，但季線還沒往上 |
| 轉弱，暫不買 | 收盤跌破季線 |
| 過熱，不追 | 單日漲幅 > 7% 或 RSI > 75 |
| 達停損 | 有持股，且收盤 ≤ 買進價 × (1 − 8%) |

訊號可能同時出現多個，例如「多方；過熱，不追」。

## 常見問題

- **某檔顯示 [錯誤]**：代號打錯、剛上市不到約 65 個交易日、或網路問題。其他檔不受影響。
- **中文顯示成方塊（圖上）**：安裝任一中文字型（Mac/Windows 內建的通常就可以）。
- **收盤價不是最新**：Yahoo 資料可能延遲，`report.csv` 的「資料日期」欄可確認。

## 選股器：每日／每週買進候選（screener.py + signals.py）

```bash
python screener.py      # 產生 candidates_daily.csv、candidates_weekly.csv、market.json
python build_site.py    # 產生 site/index.html（網頁）
```

從上市＋上櫃「成交金額前 200 名」∪「成交量前 200 名」（自動抓，已排除 ETF 與 `config.yaml` 的 watchlist）中，
套用課程「20 種買進訊號」（[signals.py](signals.py)）。兩個榜取聯集是因為有些股票單價低、成交量很大，
但成交金額排不進金額榜，只看金額會漏掉。日線每天看，週線每週六看（同一套訊號，K 棒改成週）。
每檔列出 **買進區間、停損價、停利價、賺賠比** 與白話理由，並標示「現價」在區間內、高於區間（勿追）還是低於區間。

### 買進區間（不是昨天收盤價）
| 訊號 | 買進區間 |
|---|---|
| 3、4、7、8、9、10、15、16 突破 | 突破價 ～ 突破價 +3%（超過 3% 算追高，等回測） |
| 1 回測均線 | 均線 ～ 均線 +3% |
| 16 鏡射拉回 | 高點 ×0.85 ～ ×0.90（課程的拉回可買點） |
| 17 W 底右底（左側） | 右底 ～ 右底 +3% |
| 19 假跌破（左側） | 收回支撐上方 ～ 收盤 +1% |
| 12 止跌長下影 | 今日收盤 ～ 今日最高（站穩再買） |

停損、停利與賺賠比都以**區間上緣**（最壞的成交價）計算。

**盤中不採用今天的 K 棒**：台灣時間 14:00 前執行時，Yahoo 給的今天那根還沒收完（量與價都不完整），
程式會自動略過它，改用上一個交易日的收盤資料，避免用半根 K 棒誤判突破。「+3%」在 `signals.py` 的 `CHASE_PCT` 可調整。

### 停損／停利紀律（依課程）
- **防守點**：各型態的關鍵低點（盤整低點、右底、杯柄低點…），停損放在其下方 1%
- 停損幅度 **不超過獲利目標的 1/2，也不超過 10%**；賺賠比至少 **2:1**，不合格的不列出
- 課程公式有時算出翻倍以上的目標，**停利價保守限制在 +40%**，理由欄會註明公式原值
- **停損以「收盤價」跌破為準**，不是盤中價；獲利後要自己上移停損（移動停利）

### 額外過濾與加分
- 過熱不追：RSI 太高（日線 >75）或單日暴漲 >7% 直接排除
- 長上影線爆量收黑（出貨）直接排除
- 加分：均線多頭排列（5>10>20>60 且向上）、KD 黃金交叉、放量
- **三大法人買賣超**（[institutional.py](institutional.py)）：外資＋投信＋自營商合計連續買超或賣超
  達 3 天（含）以上，會加註「三大法人連買超／賣超 N 天」，出現在候選股與搜尋結果的理由欄、
  以及觀察清單／持股的標籤裡。只是**加分項的輔助資訊，不影響買進區間、停損停利或任何進出場邏輯**。
  - 資料來自證交所、櫃買中心官方查詢介面（跟選股用的 `openapi.twse.com.tw` 同屬官方資料，
    但這兩個是網站本身在用的查詢端點，不是正式公開文件的 API），滾動保留最近 10 個交易日算連續天數。
  - 剛啟用的前幾天資料還不夠算出連續天數，看不到任何提示是正常的，之後會逐漸累積。
  - 抓不到資料就沒有任何提示，不會讓整個更新失敗。
- 網頁上方顯示「日期／大盤／櫃買／夜盤」四行，大盤偏弱時買進請更保守；後三項純粹是輔助參考，
  不影響任何買進區間、停損停利邏輯：
  - **大盤**（加權指數）：月線/季線用 yfinance 的 `^TWII` 一年歷史算（趨勢變化慢，不需要每天最新）；
    但 Yahoo 的這個資料源偶爾會延遲一兩個交易日、甚至暫時卡住不動（實測發生過），所以「今天」這
    一筆改用證交所官方的每日收盤行情查詢（可以指定日期查，比 Yahoo 準）校正，兩邊都有時用官方的。
    漲跌 % 是跟前一個交易日比較。
  - **櫃買指數**：Yahoo 對這檔（`IX0043.TWO`）沒有提供完整歷史資料，只能顯示現價與漲跌 %，
    沒辦法像加權指數一樣算月線/季線判斷多空。
  - **夜盤**：抓 Yahoo奇摩股市「台指期近一（`WTX&`）」頁面內嵌的即時報價——這是日盤＋夜盤合一
    的連續合約，跟其他看盤軟體（例如 wantgoo）的數字可能會有小差異，是不同資料商本來就會有的
    正常現象（wantgoo 那類網站用 WebSocket 即時推播，沒有簡單的 API 可以排程抓，只能放棄）。
    另外用獨立的 [night_futures.py](night_futures.py) 每天早上台灣時間約 **08:03**
    （[night-futures.yml](.github/workflows/night-futures.yml)）單獨更新一次——夜盤要到隔天
    05:00 才收盤，`daily.yml` 收盤後那幾次（14:03~16:33）跑的時候，當晚的夜盤可能才剛開盤或
    還在跑，抓到的是還沒結束的盤中價格；早上 8 點抓的才是「跑完整晚」的最終結果。
    網頁載入時會額外讀一次 `market.json`（見下方「網頁功能」），所以就算 08:03 晚於前一天
    `daily.yml` 產生網頁的時間，使用者還是看得到最新的夜盤。
  - 這三項都抓不到就不顯示，不影響其他部分的判斷。
- 同一種訊號最多列 4 檔，避免被單一訊號洗版

門檻與視窗長度都在 [screener.py](screener.py) 最上方的 `DAILY` / `WEEKLY`，可自行調整。
沒有符合的股票時清單會是空的，這是正常的。

### 效能
- 抓資料只抓 19 個月（`FETCH_PERIOD`），不是全部歷史——週線訊號需要至少 70 根週線，
  這是換算下來還夠用又不會抓太多的長度；改小之前實測過，15 個月會不夠、每週候選整批消失。
- 「[觀察清單的歷史回看](#-網頁功能github-pages)」（前 6 個交易日）會讓每檔股票的分析次數變成 7 倍，
  約佔整個分析時間的 8 成，換取的是可以回測「訊號出現後幾天走勢如何」；已經評估過改短的取捨，
  維持 6 天。真的想要更快，可以調小 `HIST_DAYS`（每少 1 天大約再快一些）。
- 自動更新流程（`daily.yml`）用 [requirements-ci.txt](requirements-ci.txt)，不裝 matplotlib
  （畫圖只有本機執行 `stock_checker.py` 才需要），`pip install` 步驟會快一點。

**這是規則篩選，不是預測，也不保證獲利。型態辨識（杯柄、三角收斂等）是用程式規則近似，
買進前請務必自己開 K 線圖確認，並看新聞與大盤狀況。**

## 我的持股（網頁）

網頁上按「＋ 記錄一筆買進」：選股票、填買進日期／買進價、選填股數、停損 %（預設 8%）、停損價、停利價。
停損價／停利價都可以留空自動算，也可以直接貼上訊號（每日/每週候選）算出的價位。之後每天（盤中也會更新，見下）：

- **趨勢**：跟觀察清單一樣，用當天最新資料判斷（多方／轉弱／過熱／觀望）。
- **停損停利分兩階段**：
  1. **固定停損**（剛買進時）：用訊號／買進時填的停損價，沒填就用 `買進價 × (1 − 停損 %)`，
     不會因為股價創新高就提早往上調。
  2. **移動停損**（trailing stop，只用在持股，觀察清單和候選股不套用）：一旦股價達到「停利參考價」，
     或季線轉弱，就永久切換成移動停損（只會切過去，不會切回來）——出場點改成跟著「買進後的最高價」
     往上調，不會往下調；股價從最高點回落到設定的停損 % 就出場。公式：`最高價 × (1 − 停損 %)`。
     參考：[什麼是移動停損停利](https://rich01.com/what-is-trailing-stop-0/)（短線建議 3~10%、波段建議 10~20%）。
- **停利參考價**：`買進價 + 風險 × 2`（賺賠比 2:1，跟 `signals.py` 的 `RISK_REWARD` 一致），
  也可以自己填目標價，永遠不變。**達到之後不是強制出場點**，而是切換成移動停損的觸發點之一——
  讓獲利有機會繼續跑，網頁會提示「可依紀律出場或續抱讓獲利繼續跑」。
- **建議**：現價 ≤ 停損（固定或移動）→ 賣出；還沒切換移動停損時短線過熱 → 提醒留意風險；其餘 → 續抱。

**預設只存在這個瀏覽器**（localStorage），不會上傳到任何伺服器——買進價、股數是敏感資料，
處理原則跟「網站不顯示持股」一致。換裝置、清除網站資料時不會跟著走；要備份就自己截圖或記錄。
只有你自己**登入帳號**後，才會另外同步一份到你自己的雲端資料（見下一節「登入與雲端帳號」），
其他人看不到，也可以完全不登入、維持只在單一瀏覽器的做法。

### 盤中價格（quotes.json）

只給「我的持股」用，觀察清單和候選股不受影響、維持每天更新。

`.github/workflows/intraday-quotes.yml` 在週一到週五**台灣時間約 9:12～13:42、每 30 分鐘**跑一次
[quotes.py](quotes.py)，兩層來源：

1. **優先：鉅亨網（cnyes）的報價介面** —— 一次可查 250 檔、上市上櫃格式相同，全市場約 5 秒。
2. **失敗才用：Yahoo 的分鐘線** —— 日線在盤中的「今天」收盤價是空的（見下方說明），要改抓
   分鐘線最後一筆才有真正的盤中成交價，全市場約 30~40 秒，比鉅亨網慢但當備援夠用。

只抓價格，不重算均線、RSI、訊號，也不會拖到或干擾正式的技術分析。抓到的價格存進 `quotes.json`，
持股會優先使用它，現價欄位下方會標「盤中」或「收盤」告訴你目前顯示的是哪一種；兩邊都抓不到時
自動退回顯示前一交易日收盤，不會出錯或空白。可能有數分鐘延遲，不是官方即時報價。

**要注意**：這兩個都是**沒有正式文件的內部介面**，不是官方公開給外部程式用的 API，也沒有深入
確認過使用條款，純粹是實測「抓得到、格式對得起來」。哪天其中一個改版、限流或擋掉，
`intraday-quotes.yml` 的執行會失敗（`continue-on-error`，不影響其他部分），持股只是暫時看不到
盤中價格、退回收盤價，不會影響觀察清單、候選股或整個網站。想調整頻率就改這個檔案裡的 `cron`。

## 登入與雲端帳號（Firebase）

讓每個人可以用自己的帳號管理自己的觀察清單和持股，彼此看不到對方的資料，也是目前**唯一的跨裝置
同步方式**——電腦、手機登入同一個帳號，改哪邊都會同步過去。

**沒設定的話完全不影響現有功能**：`template.html` 最上方的 `FIREBASE_CONFIG` 沒填之前，帳號相關的
畫面整個不會出現，搜尋、觀察清單、持股都跟今天一模一樣，只是清單和持股會只留在單一瀏覽器裡，
不會跨裝置同步。想先不管這個功能可以直接跳過這一節。

### 設定步驟（一次性，站長做）

1. 到 [Firebase 主控台](https://console.firebase.google.com) 建立一個新專案（免費 **Spark** 方案即可）
2. **Authentication → Sign-in method**：啟用 `Email/Password` 與 `Google` 兩個登入方式
3. **Firestore Database → 建立資料庫**（正式模式），建好後點 **規則（Rules）** 分頁，整段換成：
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /users/{uid} {
         allow read, write: if request.auth != null && request.auth.uid == uid;
         match /holdings/{holdingId} {
           allow read, write: if request.auth != null && request.auth.uid == uid;
         }
       }
     }
   }
   ```
   效果：只有本人能讀寫自己帳號底下的資料，其他人（包含沒登入的訪客）完全看不到、改不到。
4. **專案設定（齒輪圖示）→ 一般 → 新增應用程式 → 網頁**，複製出現的設定物件，貼進
   [template.html](template.html) 最上方的 `FIREBASE_CONFIG`（欄位是 apiKey / authDomain /
   projectId / storageBucket / messagingSenderId / appId）。**這組值不是密碼**——Firebase 的安全機制
   靠的是上一步的規則，不是隱藏這組設定，可以放心貼進去、正常 commit 上傳。
5. **Authentication → Settings → Authorized domains**：確認清單裡有 `yudi333.github.io`
   （新專案通常只內建 localhost，Google 登入在正式網域上才不會被擋，需要手動加）

改完 `FIREBASE_CONFIG` 後，重新 `python build_site.py` 上傳即可，不用改任何 Python 或 workflow。

### 資料放在哪裡
```
users/{uid}                       # 一份文件：{ watchlist: [...代號] }
users/{uid}/holdings/{holdingId}  # 一筆持股一份文件
```
登入時：本機修改一律先寫 localStorage（速度快、離線也能用），再加寫一份到 Firestore；
Firestore 用即時監聽（`onSnapshot`），另一台裝置改了，這台**開著網頁就會自動更新**，不用重新整理。
第一次登入、雲端還沒有資料時，會問要不要把這台裝置目前的觀察清單和持股匯入帳號；不是新帳號就
直接套用雲端內容。登出時會正確恢復成登入前的本機資料，不會殘留上一個帳號的內容。

### 要知道的事
- 免費 Spark 方案的額度（Firestore 每日約 5 萬次讀取、2 萬次寫入）對個人或朋友間小規模使用綽綽有餘，
  真的成長到很多人用才需要考慮升級付費方案
- 這一版只有 Email/密碼與 Google 登入，沒有做忘記密碼信件的客製化、沒有其他登入方式
- **開放給不特定的其他人用之前**，建議另外寫一份簡短的隱私聲明，讓使用者知道資料怎麼被使用、
  你會不會看到——保管別人的財務資料是有責任的，這不是技術問題，是那時候要補的一步

## 網頁功能（GitHub Pages）

`.github/workflows/daily.yml` 會在週一到週五**台灣時間約 14:03、15:07、16:33** 各自動執行一次
`screener.py` 與 `build_site.py`，做完整的技術分析並更新網頁，也可以到 GitHub 的 Actions
頁面手動按 Run workflow（跟排程執行的內容完全一樣，想跑幾次都可以）。

**為什麼完整分析不做盤中更新**：股市 13:30 收盤，盤中 Yahoo 回傳的當天日線資料收盤價是空的，會被
`stock_checker.py` 的 `drop_unfinished_today()` 濾掉、改用前一天收盤，重算均線／RSI／訊號等於白跑，
所以三次都排在收盤後：14:03 提早試著看資料是否已經齊全（沒齊全就安全地維持原狀），15:07 是留了
緩衝時間的正式版本，**16:33 是第三道保險**——遇到 Yahoo／證交所那天資料延遲比較久的日子
（會在頁面上方看到橘色提醒，見「資料延遲提醒」），這次通常就會補上；三次都還沒等到新資料
也不會出錯，網頁會維持上一次的內容，並繼續標示哪些股票資料延遲，之後你自己到 Actions 手動
按 Run workflow 重跑即可。**盤中的價格**改用另一支輕量的 `intraday-quotes.yml`（見上一節），
只給持股的移動停損檢查用；觀察清單、候選股仍是收盤後的資料。**夜盤**則是每天早上約 08:03
用 `night-futures.yml`（見上方「額外過濾與加分」的夜盤說明）單獨更新一次。

網頁內容：

- **搜尋欄**：輸入代號或公司名稱，查全部上市櫃股票（約 1,900 檔）目前有沒有符合的買進訊號，
  顯示是否建議買進、買進／停損／停利價、理由，以及 TradingView／Goodinfo／Yahoo 股市連結，可一鍵加入觀察清單。
- **我的觀察清單**：一開始是空的，每個人（不管有沒有登入）都自己選股票，不會預先幫忙塞一份清單。
  可「編輯」→ 單選或多選（也可「全選」）→ 「移除選取」。沒登入時**清單存在你的瀏覽器裡
  （localStorage）**，換手機或電腦、清除網站資料時不會同步；登入帳號後才會同步（見下）。
  - **漲跌欄**：跟前一個交易日比較的漲跌點數與漲跌幅。
  - **漲跌停標記**：收盤價正好是漲停就整格填紅色、跌停填綠色；如果當天最高價曾經觸及漲停、
    但收盤沒有守住（回落），價格文字改標紅色，最低價觸及跌停但收盤拉回則標綠色——這樣一眼
    就看得出「今天真的鎖在漲跌停」跟「衝到漲跌停但後來拉回」的差別。漲跌停價是用前一天收盤
    價 ±10%、再依台股規則的升降單位（[template.html](template.html) 的 `tickSize()`）無條件
    捨去／進位算出來的，跟證交所公告的漲跌停價一致。
- **多重訊號**：同時符合 **2 個（含）以上不同種類** 右側買進訊號的股票
  （日線、週線混合計算，同一訊號在日線與週線各出現一次只算 1 個；左側訊號與「過熱，不追」的不列入）。
  每個訊號都列出停損、停利與賺賠比，點代號可看理由。
- **跨裝置同步**：現在統一走「[登入與雲端帳號](#登入與雲端帳號firebase)」，登入同一個帳號，
  電腦、手機都會看到一樣的觀察清單和持股，改哪邊都會同步。
  （舊版曾經用 GitHub Gist 做過一套不需要帳號的手動同步，已經拿掉，改成帳號登入這一套。）
- **觀察清單的歷史回看**：每檔股票除了最新一天，還保存前 6 個交易日「回到當天重新判斷」的結果
  （收盤、漲跌、離季線、RSI、判斷，以及當天出現過的訊號與買進區間／停損／停利）。預設收合，
  點股票名稱展開在該檔與下一檔之間，也可用「全部展開」。可以用來回測：某個訊號出現後幾天的走勢如何。
  - **滾動紀錄**（[history.py](history.py)）：每次更新網頁時，先讀線上上一版的 `history.json`，加入今天的結果，
    只保留最近 7 個交易日（第 8 天起自動丟掉最舊的一天）。有記錄的日子標「**當時記錄**」（當天實際算出的結果，
    之後改規則也不會變）；還沒有記錄的日子標「**重算**」（用今天的規則回頭判斷）。
  - 紀錄只在 GitHub 上自動更新時累積；**本機執行不算**。
  - 若讀取線上紀錄失敗，會**中止該次更新**（網頁維持舊版），避免累積的紀錄被覆蓋；重新按 Run workflow 即可。
    要刻意從零重新記錄，才在執行時設 `HISTORY_RESET=1`。
- **每日／每週候選**、**大盤強弱**（見上一節）。
- **資料延遲提醒**：頁面上方的「資料日期」是**大多數股票**的最新日期，不代表每一檔都更新到那天——
  少數股票偶爾會因為 Yahoo 或證交所該天資料延遲公布，暫時停在前一個交易日。這種情況下該股票的
  標籤會多一個「資料延遲，停在 M-D」，數字（收盤、離季線、訊號）都還是那個較舊日期的；
  延遲比例夠高時（≥10% 的股票），頁面最上方會多一則橘色提醒。過一次更新通常就會恢復正常。
- 網頁不含 K 線圖，也不顯示持股、買進價與損益。K 線圖仍可在本機執行 `python stock_checker.py` 產生到 `output/`。

本機預覽：`python screener.py && python build_site.py`，再用瀏覽器開啟 `site/index.html`。

## Telegram 更新通知

[notify.py](notify.py) 已經接進 `daily.yml`（只有這個 workflow 會通知，`intraday-quotes`／
`night-futures` 頻率太高、內容也只是價格數字，不會通知）：每次收盤後完整分析跑完，會把當天的
每日候選、每週候選、多重訊號摘要傳到 Telegram；分析或發布失敗時也會另外傳一則失敗警告
（附上 GitHub Actions 那次執行的連結，方便直接點進去看記錄）。

### 設定步驟

1. 到 Telegram 找 **@BotFather**，傳 `/newbot`，照指示取名字，完成後會拿到一組 **token**
2. 跟你剛建立的機器人隨便傳一句話（不然它抓不到你的 chat id），然後打開瀏覽器輸入：
   ```
   https://api.telegram.org/bot<你的token>/getUpdates
   ```
   回傳的 JSON 裡找 `"chat":{"id":數字,...}`，那組數字就是 **chat id**
3. 到 GitHub 這個 repo 的 **Settings → Secrets and variables → Actions → New repository secret**，
   新增兩個：
   - `TG_BOT_TOKEN`：剛剛 BotFather 給的 token
   - `TG_CHAT_ID`：剛剛查到的 chat id
4. 存好之後，下次 `daily-update` 執行完就會收到通知；沒設定這兩個 secret 也完全不影響
   網站本身，只是不會有通知（`notify.py` 會自己偵測、跳過，不會讓更新失敗）

token 等同密碼，不要寫進程式碼、不要貼給別人；只放在 GitHub 的 Secrets 裡（那邊看不到明文，
連你自己之後也看不到，只能重新產生新的）。
